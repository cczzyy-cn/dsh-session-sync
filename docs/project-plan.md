# dsh-session-sync 项目方案（v0.8 基线）

> 2026-09-27 重写。本文是**计划**，不是记录；事实与证据在 `PROGRESS.md`，形状与契约以 `README.md` 为准。
> 每条结论后面都注明它是怎么被核实的；没核实的一律写成"待验"，不写成结论。

---

## 0. 结论先行

1. **"能不能做"已经过关。** 核心链路（发布 → 镜像 → 控制台浏览 → 加载更早 → 接管续聊）在线上跑通并有实测数字。
2. **没解决的是第三条腿：物化（把镜像会话写成服务器自己的真会话）。** 它能用，但它的每一次失败都需要人工介入；
   而且它有一处**结构性上限**：副本被页面打开时不能前进。这一条不是 bug，是设计边界。
3. **因此把项目拆成两条产品线**：
   - **A 核心线（同步 + 控制台）**：机器 → 目录 → 会话的浏览、完整对话阅读、接管续聊、实时跟随。**冻结新功能**，只做加固、测试、文档收敛。
   - **B 整合线（物化真会话）**：让镜像会话在服务器上就是 DSH 自己的会话（官方列表 / 官方页 / 分页 / 轨迹）。降级为**实验特性**，按 §3.2 的三条契约收敛，并给出退出条件（§3.5）。
4. **一条被实验证伪并已回退的路，不要再走**：不可能做到"副本边被读边更新"。页面一打开，DSH 就持有它的写句柄；
   而把镜像事件喂给 DSH 自己的会话，会让 DSH 从**记录者**变成**参与者**——实测它把镜像里被中断的 `tool/result` 读成回合结束，
   并在源站接下来要用的 seq 上写下 `turn/end{interrupted}` 与 `session/end-seed`（`0.6.0` 引入、`0.7.3` 整条回退）。
   **所以：实时只能是控制台；副本只能是冷档案。**

## 2. 问题清单

按"会不会让人误判 / 要不要人工介入"排序，不按工作量。

### P0 —— 会让副本变成需要抢救的资产

1. **副本被 DSH 写脏后只能人工重建。** 现行序列是：`release` → **停服**（存储层忘掉 id，仅移走文件不够）→ 移走日志 → 清 `session_projcache` → 起服 → 等一个 tick。
   `0.7.0` 的自愈只覆盖"未记账的那一段**全是** DSH 末尾标记"这一种；混合段会被正确分类但**真实分歧仍然停下来等人**。
   线上就有现成标本：`f6ba2b3b` 那条 3478 条的副本。
   *证据*：`PROGRESS.md` §2（0.6.1 事故、0.7.0/0.7.2、重建序列、第二次重建）。
2. **读到就冻结。** 页面打开副本 ⇒ 它在服务器上成为 live 会话 ⇒ `open(id,'write')` 被 `SessionAlreadyOwnedError` 拒 ⇒ 台账停在打开那一刻。
   `0.7.3` 已诚实地接受这个边界（页头显示"落后 N"），但读者没有"让我看到最新"的路——除非他用控制台。
   *证据*：`PROGRESS.md` §2「怎么会话落后」；`src/host/materialize.ts:441-460` 的注释。
3. **两端版本倾斜且不报告。** 本机 0.7.1 / 服务器 0.7.3，`state` 里没有任何版本字段 ⇒ 出问题时无法判断两端是不是同一份逻辑。
   *影响范围诚实说明*：0.7.2/0.7.3 的回退只改**服务器侧的写入路径**（写入发生在服务器），所以当前不是硬伤；但它是"必须消除的漂移"。

### P1 —— 正确性 / 体验瑕疵（不阻塞）

4. **标题是惰性的。** 副本要被"读过一次"才有标题投影（`storages/session_projcache` 生成缓存），否则 DSH 自己的列表里显示会话 id。
   `f6ba2b3b` 至今就是 id，正是因为它从没被打开过。*证据*：远端 `session_projcache/` 只有 `e08471af` 一个缓存文件。
5. **官方页每条 `workspace/changes` 打一次 `/api/changes.summary` → 404 + 一张"不可用"卡。** README §Limitations 已披露；要修就得把摘要跨链路带过来并写进 `ui-deliverables` 自己的状态表（更深的耦合）。
6. **中段空洞的修复线上从未被观测到。** 代码在（`hub.reportGap` → `holesOf` → 以洞的上沿发 `{kind:'older'}` 读页，`0.4.1`→`0.4.3` 三轮修成），
   但线上监控 24 轮 `missing=0 / holes=0`——**没坏过，所以没被看见过**。这是"有实现、无线上证据"。
7. **客户端半边几乎无自动化测试**（86 条里只有 2 条 `routing.ts` 决策测试）；端到端验证至今只能在"用户的机器 + 用户的服务器"上做，
   而每次改 host 侧都要**重启用户正在用的实例**（会杀掉当时在跑的会话）。这是本项目最大的验证缺口。

### P2 —— 工程卫生

8. **文档漂移（三处，已核实）**：
   - `PROGRESS.md` §0 表仍写 **`0.4.7`**、"最近更新 2026-09-25"，与 §2 顶部的 0.7.3 自相矛盾；
   - `README.md` §Limitations 说"中段空洞还不能被分页修"，而 `reportGap` 早已在做（stale）；
   - `README.md` 的三条路线表里 `adopt` 在**已发布的 DSH 上不存在**，`patches/` 只对 `v0.1.7-alpha.2` 有效（升版即失效）。
9. **发布纪律靠人记**：git 依赖不自建，改 `src/**` 必须重建并提交 `lib/`、`client/`（漏了线上就是"源码修了、产物没修"）。
10. **遗留物没有清理入口**：`f6ba2b3b` 副本、服务器 `/root/` 下若干 `*-copy-<ts>` 留档、本机 `%TEMP%\dsh-mat-*` 一次性实例残骸。
11. **Cloudflare 会切空闲 SSE**（DSH 的 SSE 不发心跳），未修，靠使用频率绕过。
12. **控制台是"抄"的 shipped UI**（行标记、`locales`、工具卡家族表），上游一改就会漂移，只能靠人眼比对发现。

## 3. 方案

### 3.1 两条产品线，一条边界

```text
   源站 A（Windows）                 服务器（Linux，控制台）
   ───────────────                   ──────────────────────
   发布索引 ────────────────▶  镜像（内存，尾部 4000 条滚动 + 洞修复）
   follow 事件 ─────────────▶        │
   读页 {kind:'older'} ◀─────        ├─▶ A 线：控制台（实时、可续聊）     ← 唯一的实时读数
   接管 prompt ◀─────────────        └─▶ B 线：物化器（副本日志，冷档案） ← 官方列表/官方页
```

| | A 核心线 | B 整合线 |
| --- | --- | --- |
| 能力 | 机器/目录/会话树、完整对话、加载更早、接管续聊、流式思考与输出 | 副本进入 DSH 自己的列表与官方会话页，分页/跳转/轨迹由 Host 提供 |
| 实时 | **是**（走插件自己的事件源） | **否**（冷才前进；被读着就停在快照） |
| 依赖 | 插件自己的协议（稳定） | DSH 日志格式 v4、`sessionPersistence` 契约、`agent/pre-step` 门禁、投影缓存 |
| 失败模式 | 洞 / 落后 / SSE 断流——都能自愈或如实标注 | 被 DSH 写脏、id 被存储层记住、投影缓存过期——**今天要人工救** |
| 处置 | 冻结功能，只加固 | 降级为实验特性，按三条契约收敛 |

### 3.2 B 线的三条契约（写进 README，不再含糊）

1. **冷才前进** —— 只有 `open(id,'write')` 成功（= 冷）时才追加；被读着就停在快照，页头如实说明落后多少。
2. **只读，不归档** —— 门禁（`agent/pre-step` → `{kind:'reject'}`）+ 持久化台账；归档等于"打不开"，永不使用。
3. **自带修** —— DSH 自己写的末尾标记：自动切掉（已有）；真实分歧：**自动重建**（本轮要做的），而不是"停下来等人"。

### 3.3 建议的取舍（需要你点头，见 §4）

- **D1** B 线保留、默认仍开（你此前明确要"同步会话直接使用官方页面"），但标为**实验**并给出退出条件。
  三个粒度可选，风险递减：
  - **B-全体**（现在的形状）：物化 + 每 tick 追平。官方页跟随源站，但"追加"这条路径正是所有人工抢救的来源。
  - **B-一次性**（建议考虑）：物化一次，之后**只读、不追平**。官方页拿到的是"物化那一刻的完整会话"（列表、历史分页、轨迹都在，因为整条日志都在），
    代价是源站后续的新事件不会自己长上去；好处是**根本不存在"两个写入者"**——插件再也不往那份日志里写，DSH 写什么都没人能顶歪它。
  - **B-关闭**：只剩 A 线，官方页整体消失（见 §3.1 的依赖关系）。
  > 为什么会话页这件事绕不开 B：官方页的每一样数据都按 `sessionId` 向 Host 取。镜像会话在 Host 眼里不存在，所以 `uiWorkspace.openSession(id)`
  > 只在 `state.materialized` 命中时才被调用（`src/client/routing.ts:48-54`、`src/client/SyncPanel.tsx:353-371`）；把这条缺口补上，要么让 Host 认识它（物化），要么改 Host（上游补丁，已否）。
- **D2** 接受"副本 = 冷档案"，放弃副本上的实时（0.6.0 那条路已证伪并回退）。
- **D3 ✅ 已执行（2026-09-27，用户决定"执行 scope 路线"）**：`adopt` 与 `address` 两条路线已从代码删除，控制台只剩 `scope`（纯保留、无 Host I/O）+ 自绘兜底；
  判定抽成 `routing.ts` 的 `scopeCapable` 并有测试；README 的三路线表改成一条。**先核实过线上走的就是 scope**：
  服务器 DSH `0.1.7-rc.2` 的 `dsh-api-session-controller/lib/client.js` 命中 `retainAgentScope`，而 `adopt` 在任何已发布构建里都不存在。
  `patches/` 保留为历史（已无代码路径使用）。测试 86 → **91**；产物 `client.js` −4.4 KB。
  *仍未定*：**B 线的粒度**（§4 第 1 条）。有副本时**行点击**走官方页——用户 2026-09-27 选了"保持现状"，所以 scope 面板只在"没有副本"的会话上出现。

### 3.4 路线图

每步都给出验收判据；判据必须可执行、给数字。

**Phase 0 — 对齐与卫生（约半天，零风险）**
- 修 §2 的 8 ①②③ 三处文档漂移；`PROGRESS.md` §0 重写为 0.7.3 现状。
- 本机 profile 依赖从裸 `github:` 改**钉 tag**（与服务器一致）；加**版本握手**：发布时带 `pluginVersion`（protocol 里现在没有这个字段），
  `/state` 与控制台显示两端版本及是否一致。
- 发布校验：`build-and-install.ps1` 之后产物里应含 `package.json` 的版本串（把"忘了重建"变成一条可断言的事）。
- **验收**：86 测试 + `tsc` 仍绿；`/state` 一眼看到两端版本；`PROGRESS.md` 首屏不再自相矛盾。

**Phase 1 — 关掉 P0-1：副本"自带修"（1–2 天，B 线唯一的功能投入）**
- 已有零件：`logfile.ts`（帧级解码 / 原地重写 / 清投影缓存）、`dropTrailingMarkers`、`unaccountedMarkers`（分类）、`catchUpSession` 的 `wait` 语义。
- 要做的：**自动重建**——分类判定为真实分歧且副本冷时：旧日志留档（`*.bak-<ts>`，不删）→ `release` 台账 → 用镜像原子重建 → 清投影缓存 → 重新 `mark`。
  副本热（被读着）→ `waiting`，不判死。
- **先做的实验（决定 Phase 1 成不成立）**：在**冷**会话上原地替换整份日志 + 清 `session_projcache`，**不重启** Host，看 DSH 是否按新日志重新投影。
  上轮"只能靠重启让存储层忘掉 id"的结论是在**客户端开着它**的场景下得到的，冷场景并未验过。若冷场景也失败，形态改为"清标记 + 尾部重写"，或退回"提示运维执行序列"。
- **验收**：三条失败模式各有确定性测试（纯标记 / 混合 / 真实分歧）；线上真跑一次（人为改坏一份副本的一条 content 事件 → 下一 tick 自愈，且 `state` 有记录）。

**Phase 2 — 让"实时"只有一个来源（1 天）**
- 控制台的树行 / 状态片补齐：镜像条数、落后 N、洞、副本状态（在位 / 停更 / 等待中 / 最后写入时间），并提供**重建副本**按钮（走 Phase 1 的路径）。
- README 明确写：**要实时用控制台；要官方页，看的是快照。**
- **验收**：线上打开副本页 → 页头显示落后 N；关掉页面后 30 秒内追平，页头状态随之改变。

**Phase 3 — 把端到端验证搬进仓库（1 天，收益最大）**
- 两个**隔离 home** 的一次性实例（server 用空 sessions、origin 用合成会话；`profiles\web` **不 junction 到真实 profile**——那是上一轮 rig 报废的原因），
  脚本化跑完整链：publish → 镜像 → 回填到 seq 0 → materialize → 门禁拒 prompt → 人为污染 → 自愈/重建 → 断言。
- **验收**：一条命令跑完（`node --experimental-transform-types --test "tests/e2e/*.spec.ts"` 或 `scripts/e2e.ps1`），
  不需要用户机器、不需要重启用户实例；跑完进程、端口、临时目录全部清理（本项目有残留实例的前科）。

**Phase 4 — 官方页的两处毛刺（1 天，可延后）**
- 标题：物化/追平时补一条 `session/title`（`source:{kind:'user'}` + `messageSeqs:[]`，合法形状已查证）→ 看投影是否出现；不行就改从 `sessionQuery.readTitle` 取。
- `changes.summary` 404：评估"随帧带摘要 + 写进 `ui-deliverables` 状态表"的成本；不做就继续在 README 明码标价。
- **验收**：官方列表里副本行显示真标题；404 计数为 0，或被文档固定为已知代价。

**Phase 5 — 收尾（按需）**
- SSE 心跳（若 Cloudflare 断流仍困扰）；客户端测试扩充（继续把 `SyncPanel` 的决策抽到无依赖模块）；
  文档收敛：README 保持"形状与契约"，PROGRESS 的 2026-09 之前部分归档到 `docs/history-2026-09.md`，首屏只留现状 + 未解问题。

### 3.5 停止规则（防止再陷进去）

- **B 线**：Phase 1 完成后 7 天内若仍出现一次"必须人工介入才能恢复"的副本损坏，就把 `materialize` **默认关掉**，
  README 从"默认开"改回"实验、默认关"，B 线只保留"手动一次性导出"。
- **上游耦合**：DSH 改日志格式版本（v4 → v5）或改 `sessionPersistence` 契约 ⇒ B 线立即冻结，先适配再谈功能。
- **不做**：不引入新的 Host 源码补丁（`adopt` 那条已弃）；不 fork 上游；不把"实时"押在任何 DSH 会去写的东西上。

### 3.6 工程纪律（用血换来的，写死在文档里）

- 新写的测试要**在旧代码上跑一遍**，否则不知道它测的是什么。
- 端到端断言**最终状态**，不要阻塞等待一个已经流逝的瞬时状态。
- 任何"永远完不成"的现象，先量**体积 / 条数**，与两端的硬上限对一遍（12 MB vs 4 MB 那次）。
- 修"数据在 A 处、要用在 B 处"的缺陷，**第一步先问这两处在不在一起**（header 那次绕了三轮）。
- 生产验证必须给**数字**（seq 范围、条数、字节、耗时），不接受"好了"。
