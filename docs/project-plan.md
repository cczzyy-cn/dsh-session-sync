# dsh-session-sync 项目方案（v0.8 基线）

> 2026-09-27 修订。本文是**计划**，不是记录；事实与证据在 `PROGRESS.md`，形状与契约以 `README.md` 为准。
> 每条结论后面都注明它是怎么被核实的；没核实的一律写成"待验"，不写成结论。
>
> **本版的最大变化**：B 线（"把镜像写成服务器自己的真会话"）已被用户否掉并**整条移除**——不是关掉，是删掉。
> 下面 §3.1 的"两条产品线"因此收敛成一条。

---

## 0. 结论先行

1. **这个插件现在只做一件事**：把选定的会话发布到同步服务器，在服务器的控制台里读它、并接管续聊。
   会话数据从源站来，控制台是唯一的阅读面，也是唯一的**实时**读数。
2. **"镜像会话在服务器上变成真会话"这条路被证伪并被移除。** 理由是结构性的，不是口味问题：
   - DSH 会往它打开的会话里写东西（带 seed 恢复时补 `session/end-seed`；在里面发言会留下回合骨架），而副本必须与源站逐格对齐；
   - 于是副本**只能在冷的时候前进**——而"有人正开着它"恰恰是它不能前进的原因（读到即冻结）；
   - 把事件喂给 DSH 自己的会话来保持实时，会让 DSH 从**记录者变成参与者**（实测：镜像里被中断的 `tool/result` 让 Host 把副本的回合结束了，占用了源站下一步要用的 seq），`0.6.0` 引入、`0.7.3` 整条回退；
   - 剩下的一切失败都要人来救（`release` → 停服 → 移日志 → 清投影缓存 → 起服），而它的收益只是"官方页面的外壳"。
3. **因此不再有"两条线"的取舍**。控制台 = 阅读面；`scope` 路线（`ctx.sessions.retainAgentScope`，本仓库已核实线上存在）让面板内部用的就是 DSH 官方的会话组件；
   官方**整页**（工作区列表、Host 分页、Host 轨迹）不再追求——那需要 Host 认识这条会话，而唯一能让 Host 认识它的手段就是物化（已删）。

## 2. 问题清单（移除物化之后剩下的）

### P0 —— 会咬人的

1. **端到端验证只能在用户的机器上做。** 改 Host 半边要重启用户正在用的实例（会杀掉当时在跑的会话），所以"改完就能验"这件事做不到。
   这是本项目最大的缺口，也是过去几轮"只有真跑起来才现形"的缺陷一再出现的原因。
2. **本机 Host 半边仍是旧加载。** 客户端半边刷新即生效，Host 半边（`lib/`）要一次重启；在那之前本机跑的是旧代码，
   而**发布纪律要求 `lib/`、`client/` 与源码一起提交**（git 依赖不自建）。
3. **服务器上两份旧副本的去留未定。** 门禁随代码消失，它们在服务器的 DSH 里变回普通会话：能打开、也能被发言
   （发言会在副本里长出轮次，而副本已不再被插件跟进）。要么留着当历史，要么按"停服 → `mv` 走日志与投影缓存 → 起服"清掉。

### P1 —— 正确性 / 体验瑕疵

4. **中段空洞的修复线上从未被观测到**（`reportGap`/`holesOf` 有实现、有单测、有合成端到端，但线上 24 轮 `missing=0`）。
5. **Cloudflare 会切空闲 SSE**（DSH 的 SSE 不发心跳），未修，靠使用频率绕过。
6. **控制台是"抄"的 shipped UI**（行标记、`locales`、工具卡家族表），上游一改就会漂移，只能靠人眼比对发现；`scope` 路线只是让**对话**不再抄。
7. **接管续聊（写回源站）近期没有回归验证**——它一直在，但这几轮没人碰过它的端到端。

### P2 —— 工程卫生

8. **文档收敛**：`PROGRESS.md` 1100 行，2026-09 之前的日志该归档；`docs/host-side-session-plan.md` 是被否掉那条路的计划书，只应作历史保留。
9. **`patches/`**（adopt 补丁）已无代码路径使用，留作历史。
10. **发布校验靠人记**：产物里应含 `package.json` 的版本串（把"忘了重建"变成可断言的事）。

## 3. 方案

### 3.1 一条产品线

```text
   源站 A（Windows/任意）                 服务器（Linux，控制台）
   ─────────────────────                  ──────────────────────
   发布索引 ─────────────────────▶  镜像（内存，尾部 4000 条滚动 + 洞修复）
   follow 事件（含流式文本）──────▶        │
   读页 {kind:'older'} ◀──────────        └─▶ 控制台：机器 → 目录 → 会话树
   接管 prompt ◀──────────────────              + 官方组件画的对话（scope 路线）
                                                 + 接管输入框 + 插件自己的分页
```

| | 控制台（唯一阅读面） |
| --- | --- |
| 能力 | 机器/目录/会话树、完整对话、加载更早、接管续聊、流式思考与输出 |
| 实时 | **是**（走插件自己的事件源，不经过 Host 的会话生命周期） |
| 依赖 | 插件自己的协议 + `scope` 特性探测（`retainAgentScope` + `binding`） |
| 失败模式 | 洞 / 落后 / SSE 断流——都能自愈或如实标注 |

**契约（写进 README）**：

- 镜像只读、内存态、尾部窗口；洞由 `reportGap` 定点读页修，落后由 replay 修。
- 控制台是唯一的阅读面；它画的是 DSH 官方组件（`scope` 路线），但外壳、分页、输入框是插件的。
- **插件永远不写 DSH 的会话日志。** 这是被证伪那条路留下的最硬的一条规矩。

### 3.2 不做什么（明确的负向清单）

- 不物化、不写别人的日志、不归档、不挂 `agent/pre-step` 门禁。
- 不追求"官方整页"——除非上游出现"Host 能读一条它没有的会话"的接缝（那是 Host 侧改动，本项目不做）。
- 不引入新的 Host 源码补丁（`adopt` 那条已随补丁失效而删）；不 fork 上游。

### 3.3 路线图

每步都给验收判据；判据必须可执行、给数字。

**Phase 0 — 卫生与对齐（约半天）—— 本版已完成大半**

- ✅ 已完成：`scope` 收口（删 adopt/address）、物化整条移除、README/PROGRESS/本文同步、`tool-cards.ts` 的既有类型错。
- 待办：**版本握手**——发布时带 `pluginVersion`，`/state` 与控制台显示两端版本及是否一致（今天两端倾斜是"看文件才知道"的）。
- 待办：发布校验加一条"产物里含 `package.json` 的版本串"。
- **验收**：`/state` 一眼看到两端版本；产物校验脚本化。

**Phase 1 — 把端到端验证搬进仓库（1 天，收益最大）—— 2026-09-27 做了第一档**

- ✅ **进程内整链**（`tests/e2e-chain.spec.ts`）：真 server-role 引擎（自起监听）+ 真 client-role 引擎（自开链路）+ 真镜像，
  源站是一个 `SessionController` 替身。串起六件事：发布 → 镜像窗口 → 读页（边界钉在"下沿 + 1"）→ **那一页真的到达镜像** →
  **接管**（`submitCommand` → 源站 `prompt` 收到文本 → 控制台收到 `accepted`）→ 契约守卫（`state` 里没有 `materialize`）。
  0.3 秒跑完，不需要 DSH、不需要用户机器、不占 3098/3099。测试总数 28 → **29**。
- 待办：**真实例那一档**——两个隔离 home 的 `dsh web`（`profiles\web` **不 junction 到真实 profile**，那是上一轮 rig 报废的原因；
  `DSH_HOME` 要包一层 `.ps1` 才能注入），验"插件能在真 DSH 里加载、真 `SessionController` 的行为是否与替身一致"。
- **验收**：这一档也要一条命令跑完，且跑完进程、端口、临时目录全部清理（本项目有残留实例的前科）。

**Phase 2 — 控制台的诚实性（1 天）**

- 树行 / 页头补齐：镜像条数、落后 N、洞、源站在线与否；接管命令的状态（queued/delivered/accepted/failed/expired）在页面上可见。
- **验收**：故意断源站 → 页面显示落后/离线而不是静默不变；恢复后自动追上。

**Phase 3 — 收尾（按需）**

- SSE 心跳（若 Cloudflare 断流仍困扰）；客户端测试继续把决策抽到无依赖模块；
- 文档收敛：`PROGRESS.md` 的 2026-09 之前部分归档到 `docs/history-2026-09.md`，首屏只留现状 + 未解问题。

### 3.4 停止规则

- **不重新引入"把镜像写成 DSH 会话"这条路**，除非上游给出官方接缝；再讨论时先读 `PROGRESS.md` §2 的两次证伪记录。
- 上游改日志格式或 `sessionPersistence` 契约与本插件无关（已无耦合）；改**客户端会话服务**（`retainAgentScope`/`binding`）则 `scope` 路线失效 → 退回自绘面板，**功能不减**。
- 若 `scope` 路线在某次 DSH 升级后消失，**不补丁上游**：自绘面板就是兜底。

### 3.5 工程纪律（用血换来的）

- 新写的测试要**在旧代码上跑一遍**，否则不知道它测的是什么。
- 端到端断言**最终状态**，不要阻塞等待一个已经流逝的瞬时状态。
- 任何"永远完不成"的现象，先量**体积 / 条数**，与两端的硬上限对一遍（12 MB vs 4 MB 那次）。
- 修"数据在 A 处、要用在 B 处"的缺陷，**第一步先问这两处在不在一起**（header 那次绕了三轮）。
- 生产验证必须给**数字**（seq 范围、条数、字节、耗时），不接受"好了"。
